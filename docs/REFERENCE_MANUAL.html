PlanX Urban Procedural 3D

Parametric 3D zoning and urban design laboratory • v0.5.2

1. Overview

PlanX Urban Procedural 3D is a parametric 3D zoning and urban design tool that bridges QGIS vector layers with a browser-based Three.js cockpit. Users select a polygon parcel layer, launch a local 3D scene, and interactively adjust building typologies, setbacks, floor counts, roof styles, land uses, and zoning constraints through draggable sliders and 3D handles. A real-time compliance dashboard reports BCR, FAR, building height, PlanX Score, constraint load, population estimates, carbon footprint, and stormwater runoff. Design parameters are synchronised back to the QGIS attribute table in a single click.

2. Feature Documentation

2.1 Architecture

The plugin has four components: (1) a QGIS PyQt dialog for layer selection and server configuration, (2) a Python ThreadingHTTPServer serving GeoJSON and handling sync POST requests, (3) a ~6,900-line Three.js browser application with procedural city generation, and (4) a _SyncBridge QObject that safely marshals sync calls from the HTTP server thread to the QGIS main thread.

2.2 3D In-Scene Editing Handles

Four Draggable Handles

  • Z Height Handle (teal arrow): Drag vertically to change floor count; model rebuilds live.
  • Setback Handle (teal torus ring): Drag radially to adjust setback distance.
  • X Scale Handle (red double-arrow): Adjust mass scale along the OBB X axis (0.35–1.60).
  • Y Scale Handle (blue double-arrow): Adjust mass scale along the OBB Y axis (0.35–1.60).

All handles disable OrbitControls during drag and use ray-plane intersection for position computation.

2.3 Heatmap Modes

Four Visualisation Modes

  • Score: Red (<55) to amber (55–76) to green (76+).
  • Compliance: Slate (compliant) vs. dark red (violation).
  • Density: Blue (low) to amber to violet (high, ≥800 pp/ha).
  • Carbon: Green (low intensity) to amber to red (high intensity).

2.4 Procedural Roads and Traffic

Inferred Road Network

Road corridors are inferred from parallel-facing boundary segments between different parcels. Classification by corridor width: Boulevard + Tram (≥32 m), Urban Avenue (≥24 m), Collector Street (≥15 m), Local Street (≥10 m), Shared Slow Street (otherwise). Intersections are classified as roundabout (3+ arms or steep-angle crossing) or signalised. Animated vehicles follow road curves with headlights/taillights visible at night.

2.5 Day/Night Cycle and Procedural Facades

Solar Animation and Window Textures

Solar slider 6:00–22:00 with Play/Pause animation. Procedural sky dome shader with stars at night. Directional light moves along a 3D arc. Night mode activates emissive building window maps (multi-coloured glows), streetlight bulbs, and traffic headlights. Facade textures are canvas-drawn per-floor window grids (4 columns/floor), with ground-floor shopfronts (MixedUse/Commercial) or entrance doors (Residential/Civic). Lit/unlit window randomisation determines the emissive pattern for night glow.

5. Urban Metrics

PlanX Score

A 0–100 composite score computed as:

Score = 42 + FAR_utilisation(24) + open_space_share(16) + runoff_score(10) + density_score(8) − violation_penalty(max 55)

The violation penalty aggregates BCR excess (×28), FAR excess (×34), height excess (×26), and zero-footprint penalty (28). Scores ≥76 = green, 55–75 = amber, <55 = red.

8. Workflow Guide

  1. Load a polygon parcel/block layer into QGIS. A projected CRS in metres is recommended; geographic CRS layers are auto-projected to EPSG:3857 with a warning.
  2. Click the PlanX Urban Procedural 3D toolbar icon to open the dialog.
  3. Select the polygon layer. Optionally select specific features—only selected features are exported.
  4. Choose a port (default 8090; auto-falls forward up to 20 ports if busy) and click Start 3D Cockpit.
  5. The browser opens with the Three.js scene. Click any parcel to select it; the right panel shows all controls and live metrics.
  6. Adjust typology, usage, setbacks, floors, floor height, roof style, mass scales, stepback parameters, or zoning limits. Everything updates instantly.
  7. Use the heatmap selector to visualise score, compliance, density, or carbon patterns across all parcels.
  8. Use Auto-Solve City or Apply to All for batch operations. Use the 3D measurement tool for distances.
  9. Click Sync Parameters to QGIS to write all modified parcel attributes and optional geometry back to the QGIS layer.

9. Two-Way QGIS Synchronisation

Thread-Safe Attribute and Geometry Sync

The /sync POST endpoint receives a JSON payload with per-feature updates. A _SyncBridge QObject marshals the update from the HTTP server thread to the QGIS main thread via pyqtSignal, with a 30-second timeout. The plugin auto-creates 27 PlanX-specific attribute fields (far, bcr, gfa, setback, scale_x, scale_y, floors, usage, floor_h, typology, max_bcr, max_far, max_height, roof_style, stepback_i, stepback_d, plan_score, const_load, height_m, z_base, z_top, pop_est, carbon, runoff, open_space) and optionally updates geometry from the setback ring coordinates re-projected to the layer's original CRS. All writes are transactional via beginEditCommand()/endEditCommand() with full rollback on failure.

10. Technical Notes

  • CRS handling: Geographic CRS layers are auto-projected to EPSG:3857 for export. Sync writes geometry back through reverse projection to the original layer CRS.
  • Thread safety: Server callbacks run on worker threads. _SyncBridge uses Qt signal/slot to marshal to the main thread with a 30-second timeout.
  • Graceful degradation: Building construction failure falls back to Tower, then to parcel footprint only. Setback consuming the entire parcel progressively rolls back and ultimately uses OBB shrink.
  • Polygon operations: Pure JavaScript: offset polygon ring (straight skeleton approximation), OBB, shoelace area, convex polygon clipping, line intersection, ring normalisation—no external geometry libraries.
  • Procedural textures: Facade window textures are canvas-drawn at runtime (4 columns/floor, usage-dependent colours, separate emissive maps).
  • QGIS compatibility: 3.28 through 4.99. Cross-version field creation via QMetaType/QVariant fallback. Scoped enum handling for Qt5/Qt6.
